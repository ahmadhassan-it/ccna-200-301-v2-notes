2. BREAK A (first try): PC1 mask 255.255.255.252
============================================================
   IPv4 Address....................: 192.168.20.10
   Subnet Mask.....................: 255.255.255.252
   Default Gateway.................: 192.168.20.1

PC1> ping 192.168.20.100
Reply from 192.168.20.100 x4, 0% loss   (still worked!)

PC1> tracert 192.168.20.100
  1   0 ms      0 ms      0 ms      192.168.20.1
  2   13 ms     0 ms      0 ms      192.168.20.100
Trace complete.

Lesson: the packet went through the router. A wrong setting can still show a working ping.
Packet Tracer may be more lenient than a real PC (not confirmed).

============================================================
3. BREAK A (redone): PC1 IP on the wrong network
============================================================
   IPv4 Address....................: 192.168.30.10
   Subnet Mask.....................: 255.255.255.0
   Default Gateway.................: 192.168.20.1

PC1> ping 192.168.20.100
Request timed out. x4   (100% loss)

PC1> ping 192.168.20.1
Request timed out. x4   (100% loss)

Fix: IP back to 192.168.20.10, mask 255.255.255.0
PC1> ping 192.168.20.1 and ping 192.168.20.100: both reply.

   DNS Servers.....................: 192.168.20.100

5. BREAK C: shutdown on SW1 Fa0/2
============================================================
SW1# show interfaces status
Fa0/2                        disabled 1          auto    auto  10/100BaseTX

PC2> ping 192.168.20.1       -> Request timed out. x4 (100% loss)
(ipconfig on PC2 still showed the same IP, mask, gateway and DNS)

Fix on SW1:
Switch> enable
Switch# configure terminal
Switch(config)# interface fa0/2
Switch(config-if)# no shutdown
Switch(config-if)# end
